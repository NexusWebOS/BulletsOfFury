# Bullets of Fury — ten themed HUD kits
Generated October 7, 2026 with the built-in image_gen tool.

Mike's requested revisions are the authority: solid glowing meters, ship/missile counter icons, optional secondary enemy shield bars, ten stage themes and distinct matching miniboss frames.

## Contents of each theme
Each PNG is one concept sheet with five separate components, in this order:
1. Player HUD: roll/somersault, equipped weapon, named special, speed/player-shield pips, radar, incoming lock and life/missile counts.
2. Boss HP with a thin secondary shield meter.
3. Boss HP only, using a shallower housing with no second track.
4. Distinct compact miniboss HP with a thin secondary shield meter.
5. Compact miniboss HP only, with no second track.

These are alternatives; the four enemy examples are not meant to appear together during play. Counts, names, icons and fill percentages in the concept sheet illustrate the layout.

## Shared visual rules
- Every long meter uses one continuous luminous fill. No equals-sign styling, blocks, ticks or internal dividers.
- This includes roll, somersault, special ability, boss HP, miniboss HP and secondary enemy shields.
- Maneuver fills remain green; special remains red; enemy HP remains amber/orange; shields remain cyan. Frames carry the biome colors so meter meaning is stable between levels.
- SPEED and the player's upgrade SHIELD indicators are still discrete pips. They represent equipment levels and are not long health/cooldown meters.
- Both count tabs include the appropriate ship or missile icon beside the value. Runtime integration should draw the current pilot's existing nli_/nmi_ authored icons, rather than baking a sample icon/count into every frame.
- Glows are restrained internal highlights and pixel rims. Avoid large soft bloom that obscures text or bullets.
- Unshielded bars omit the shield row entirely. At runtime choose by actual shield capability, not by whether current shield HP happens to be zero.
- Miniboss bars share the stage materials but use different, smaller endcaps and nameplates.

## Files and production boundary
Open review.html to inspect all ten sheets on light/dark backing. The per-stage folders keep art, theme notes and prompt provenance together. prompts.json stores the exact prompt history. manifest.json records dimensions, source paths, hashes and alpha facts.

Generated sources are stored outside assets/game and are not preloaded by the browser game. Original generated bytes are preserved. No runtime script or shared atlas is changed in this art pass. The v1 HUD concept remains available in the sibling hud_concept_1007 folder.

Before installation, separate the chosen static shells from live labels/icons/fills, register clean source rectangles, test native-size lettering and reserve player/boss HUD geometry before asynchronous assets load. Load only the current stage skin; reuse common glow strips and fonts across all ten. Do not decode all ten large concept sheets in the game or make a new texture per fill percentage.

The sheets are reviewed concept assets, not a claim of pixel-exact interchangeable atlas geometry or measured FPS improvement. Enemy health/shield bindings, multi-enemy encounters, co-op ownership and the native game HUD still require integration.
