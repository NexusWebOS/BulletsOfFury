# ColeForge Art Direction

## Standing sprite clarity rule

When this work creates, exports, integrates or reviews sprites or raster game art/animation, apply [the ColeForge sprite clarity standard](../coleforge-sprite-clarity/SKILL.md). Blurry or muddy finished frames are not acceptable; use direct master exports and verify the actual animation at its intended game/display size.


Read `coleforge-portability` for the rendering contract. Use
[references/style-foundation.md](references/style-foundation.md) for inspected ColeForge evidence,
its limits and where to find existing art. Separate explicit rules, observed traits, and proposed
new choices; never label a draft palette or an unreviewed mockup Mike's approved signature.

## Establish the visual system

Inspect relevant BOF/project screens and original assets at native scale. Select a small set
representing gameplay, HUD/menu, enemy/boss, environment and effects as the task needs. Record
the version and source, not just an attractive crop. Reuse existing typography, frames and icons.

Define shape language, silhouette, value hierarchy, palette roles, outline/edge treatment,
material treatment, view/perspective, texture density, lighting baked into art, and motion rhythm.
Choose rules that survive a new genre; avoid forcing military HUD imagery onto every ColeForge game.
Specify actual colors only after sampling approved assets. Identify enemy shots, player shots,
danger, pickups and interaction states by more than hue alone.

## Produce coherent families

Write briefs with subject/state, view/facing, identity reference, game-scale dimensions,
palette/material locks, cell/pivot, alpha policy, animation states and required output metadata.
Approve or use an established representative asset before multiplying variants. Preserve
identity and scale across the family. Scope approval to what was actually approved.

Use SpriteCook/image-generation tools for raster production when applicable; use model/DCC
tools for meshes. Keep generation and cleanup in the authoring pipeline. Do not replace missing
art with browser decoration. Use the installed character animation skill for gait/root review.

## Acceptance

Inspect the source, native-scale contact sheet and integrated scene. Check silhouettes over
actual backgrounds, UI hierarchy, sprite size/pivots, complete extents, palette continuity,
edge contamination, legible states and animation stability. Style consistency must be judged
in play as well as a showcase sheet. Preserve source files, rights notes and export metadata.

Deliver a compact style record and the requested assets/screens. Distinguish confirmed standards,
project-specific choices and proposed extensions so later work can maintain them accurately.


## Sprite-tool handoff

Use `coleforge-sprite-tools` to choose the source editor and export handoff. Default new sprite sources to `coleforge-aseprite`; retain existing Pixelorama/LibreSprite projects. Preserve approved palettes, native pixels, layers and identity through export; tool choice does not establish a new ColeForge style.
## Selected arcade video references

When a ColeForge request calls for Mike’s selected arcade influences, use `coleforge-arcade-studies` to retrieve focused source images and study findings. Assign approved project art to identity and choose one lead reference per pose, environment, material or presentation job. Golden Axe, X-Men, T2, Reloaded, Battletoads and sports recordings are distinct visual families; do not average them or impose shared console budgets. The library includes explicit version and visual-review limits.
## Standing retro reference direction

Mike adopted the selected reference styles as an ongoing default for all his 16-bit and retro games on November 6, 2026. Apply [the standing retro art direction](references/retro-art-direction.md) for relevant new art and requested visual work, including retro-styled host games and native builds. Choose the genre/camera family, preserve approved identity and current instructions, and use actual inspected image inputs. The linked guide records the adopted visual qualities, existing sheet-library roles and target adaptation; it does not establish an exact universal palette or unauditioned sonic identity.
